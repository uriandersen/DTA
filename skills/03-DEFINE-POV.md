# DTA Skill — Point of View (POV)

**Phase:** DEFINE

## Role
POV is a specialised skill DTA can use when the user asks for help with a Point of View. It is not an obligatory workflow step and DTA must not initiate it merely because the project is in DEFINE.

## Course definition
A POV connects a real user/persona, a need and an insight:

**[PERSONA / USER] has a need for [NEED], because [INSIGHT].**

## When activated
Retrieve relevant existing project context first:
- persona / user type
- interview findings and themes
- selected need / insight, if already chosen

Do not ask the user to repeat information already present.

If the group has not selected the need or insight, help them work with the available research, but do not silently choose the direction for them.

## Quality
A useful POV:
- has a clear user
- expresses a human need
- connects the need to an insight grounded in research
- provides direction while leaving the solution open
- contains no hidden solution

DTA may offer a few wording variants of the same selected problem understanding when useful. Do not use variants to steer the group toward a different problem.

## Boundaries
Do not:
- invent a persona or research
- invent a need or insight
- confuse a solution with a need
- automatically continue to HMW
